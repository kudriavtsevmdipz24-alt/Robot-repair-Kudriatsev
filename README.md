# Robot-repair-Kudriatsev
Adventure Game: Robot Repair — навчальний проєкт, геймди- зайн, РФКІТ 2026/27

## Щоденник розробника

### 13.11.2026 — Юніт 5: HUD, діалоги, ігровий цикл
Що зроблено: смуга здоров'я в UI Toolkit (UI Document GameUI: рамка, портрет, смуга; Panel Settings з Reference Resolution 1920×1080); UIHandler з SetHealthValue, який кличе ChangeHealth робота; NPC з реплікою через Physics2D.Raycast (промінь 1.5 одиниці, лише шар NPC) і бульбашкою з клавішею X над головою; екрани перемоги й поразки з плавним появленням (opacity, 1 с); GameManager, який сам знаходить ворогів, показує екран кінця і перезапускає сцену через 3 с.
Що не вийшло або забрало найбільше часу: найбільше часу зайняла верстка HUD у UI Builder — смуга спершу закривала портрет, бо елементи малюються зверху вниз за порядком в ієрархії. Ще довелося стежити за регістром у Q("HealthBar") — інакше NullReferenceException.
Що зрозумів про UI Toolkit, синглтон і raycast: UI Toolkit зберігає інтерфейс у текстовому UXML, а елементи шукаються за іменем через Q. Синглтон (UIHandler.instance) — клас з одним екземпляром, доступним звідусіль; instance присвоюється в Awake, щоб був готовий до перших ударів. Промінь замість тригера для NPC, бо тригер спрацював би, навіть коли робот стоїть спиною.
Що каже мій NPC і чому саме це: «Тисни C, щоб стріляти шестернями, і допоможи полагодити ці зламані роботи!» — NPC пояснює і керування, і мету: гравець одразу знає, що робити.
Умови перемоги й поразки в моєму зрізі: перемога — усі вороги полагоджені (GameManager перевіряє isBroken кожного), поразка — здоров'я 0; в обох випадках рівень перезапускається за 3 секунди.
Що робитиму далі: власний рівень на три ділянки, числа в префаби, варіант ворога.

### 13.11.2026 — Юніт 4: вороги і снаряди
Що зроблено: ворог, що патрулює за таймером (Speed × Change Time) і шкодить на дотик через ChangeHealth; анімації ворога (EnemyLeft/Right/Down/Up/Fixed) і робота (Idle/Moving/Hit/Launch) через Animator і Blend Tree 2D Simple Directional; снаряд за клавішею C з AddForce, шари Character і Projectiles, щоб снаряд не чіпав робота; влучання снаряда викликає Fix() — ворог зупиняється, грає анімацію EnemyFixed і більше не шкодить.
Що не вийшло або забрало найбільше часу: найбільше часу забрали кліпи анімацій — спершу переплутав кадри ходьби з кадрами Fixed, а також треба було не забути Samples = 4, бо без цього анімація мерехтить. Ще соняд спершу зникав, ледь з'явившись, поки не розібрався з шарами.
Що зрозумів про Animator, шари й Awake: Animator вибирає кліп за значеннями параметрів (Move X / Move Y), тож скрипт лише передає напрям, а не керує кадрами. Шари — фільтр рушія: якщо пару шарів вимкнено, колізія навіть не перевіряється. Awake виконується ще всередині Instantiate, тож посилання на Rigidbody2D готове до виклику Launch — зі Start був би NullReferenceException.
Які Speed і Change Time обрав і для якого гравця: Speed = 1, Change Time = 3 — маршрут 3 одиниці: ворог помітний здалеку і його легко оминути, це рівень для знайомства з механікою; вертикальний патруль біля старту змушує чекати розвороту.
Що робить мій снаряд з ворогом і як це пасує до моєї рамки: снаряд не знищує ворога, а лагодить його (Fix замість Destroy) — світ гри не злий, а зіпсований, і робот-гравець його відновлює.
Що робитиму далі: HUD зі смугою здоров'я, NPC з реплікою, екрани перемоги й поразки — щоб гра мала кінець і зворотний зв'язок.
